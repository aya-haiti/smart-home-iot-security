    Vulnérable ou sécurisé ?

    Chaque attaque est évaluée contre les deux configurations par le même moteur que l'onglet « Attaques ».

    Attaquant anonyme, sauf la dernière ligne : identifiants volés d'un capteur (sensor_user).

    Broker vulnérable — port 1883
    listener 1883 0.0.0.0
allow_anonymous true

    Aucune authentification, trafic en clair, aucun contrôle d'accès par topic.

    Broker sécurisé — port 8883
    listener 8883 0.0.0.0
tls_version tlsv1.2
allow_anonymous false
password_file /mosquitto/config/passwords
acl_file      /mosquitto/config/aclfile
max_connections 50
message_size_limit 8192
    ACL par rôle (aclfile)
    user sensor_user
topic write home/+/temperature/state
topic write home/+/gas/state
topic write home/+/door/state

user actuator_user
topic read  home/+/light/cmd
topic write home/+/light/state
topic read  home/+/ac/cmd
topic write home/+/ac/state

user dashboard_user
topic read  home/+/+/state
topic write home/+/light/cmd
topic write home/+/ac/cmd

    À retenir

    • TLS + authentification bloquent l'accès anonyme : espionnage et injection deviennent impossibles sans identifiants.
    • L'ACL limite les dégâts d'un compte volé : un capteur ne peut ni lire les autres topics ni commander les actionneurs.
    • Limite : un compte capteur volé peut encore publier de fausses mesures sur son propre topic, et la configuration ne limite pas le débit. La détection d'anomalies Node-RED reste nécessaire (défense en profondeur).
